# Deployment

Routine releases use the GitHub deployment workflow on main. Run the existing checks/build before publishing. Do not manually upload or invalidate when automation is available. Confirm the exact commit’s successful deployment job before testing live. The workflow captures recovery assets, retains existing objects, publishes assets before HTML and verifies origin/public hashes. Failed acceptance restores the predecessor and fails the run. Inspect failed-step logs before retrying. Keep all checks and environment protections enabled. Never commit unrelated working changes or use an older source snapshot over newer live content. Infrastructure, credentials and database changes are separate reviewed operations. Documentation-only changes do not trigger deployment.
